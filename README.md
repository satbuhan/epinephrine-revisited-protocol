# Epinephrine/Adrenaline Revisited — Contemporary Decision-Making Algorithm

An interactive, referenced walkthrough of the manuscript's own Figure 1:
the contemporary decision-making algorithm for using epinephrine in
anaphylaxis, cardiac arrest and the three major shock subtypes (septic,
cardiogenic, obstructive) — plus the adverse-effect monitoring obligations
and evidence summary that apply across all of them. Every box and decision
point in all four diagrams can be selected to reveal, in one place: what
the step means, why the algorithm calls for it, and the sources behind it.

**Live site:** https://satbuhan.github.io/epinephrine-revisited-protocol/

**Authors:** Dr. Özgür Karcıoğlu & Dr. Satuk Buğra Han Bozatlı

## Why this exists

A flowchart alone tells a reader *what* to do at each step but not *why*,
and a reader outside the authors' own team cannot easily check the
evidence behind a specific box (why IM, not subcutaneous, for anaphylaxis;
why timing relative to defibrillation matters in cardiac arrest; why the
same drug is second-line in septic shock but a last resort in cardiogenic
shock). This page keeps the original algorithm exactly as authored, and
attaches the clinical reasoning and literature to each box without
cluttering the diagram itself.

The algorithm this page presents is Figure 1 of "Epinephrine/Adrenaline
Revisited: Caveats and Pitfalls in Pharmacology and Clinical Practice,"
drawn as a dedicated vertical-algorithm figure of three parallel decision
lanes (Anaphylaxis / Cardiac Arrest / Shock States) plus a disconnected
monitoring & evidence-summary panel.

## Status

This is a working version, built to be tested on both desktop and mobile.

- **Reference verification for this tool differs from the rest of the
  atlas — by explicit author instruction, not by oversight.** For every
  other tool here, each reference is independently re-verified against a
  live primary source before being used (see `METHODOLOGY.md`). For this
  tool, Dr. Bozatlı explicitly instructed that the manuscript's own
  57-entry reference list should be taken as-is: Dr. Karcıoğlu has already
  evaluated it and it is accepted as correct on that basis, without a
  separate independent re-verification pass for this build. Every entry's
  `kind` field in `assets/content.js` says so plainly ("As cited in the
  manuscript; not independently re-verified"). If that changes, update
  this section and the affected entries' `kind` fields together.
- The diagram's four panels, their box text, and the branching logic were
  transcribed directly from the authors' own Figure 1 slide (rendered to
  an image and inspected directly, not just text-extracted) and
  cross-checked against the companion graphical abstract and the
  manuscript's own section text.

## Disclaimer

This is an academic / educational reference tool, not a substitute for
institutional protocol or bedside clinical judgement. Verify any dose or
timing against current local protocol before clinical use.

## How it's built

Plain HTML/CSS/JS, no build step and no framework — a single static site
that GitHub Pages can serve directly.

```
index.html          page structure — four panel sections (Anaphylaxis,
                     Cardiac Arrest, Shock States, Monitoring & Evidence
                     Summary), each its own diagram
assets/style.css     design (the "paper" masthead/references,
                     the diagram scope + readout panel)
assets/content.js     ← single source of truth for every node's text,
                     and reference list. Edit this file to change
                     what the page says.
assets/app.js         rendering + interaction (builds all four diagrams
                     and their connector lines from content.js, handles
                     the click-to-expand panel on desktop and the bottom
                     sheet on mobile)
```

### Running it locally

No install needed:

```bash
python3 -m http.server 8000
# open http://localhost:8000
```

### Editing content

Open `assets/content.js`. Each entry in `NODES` is one box or decision
hexagon from one of the four diagrams (`meaning`, `rationale`, and `refs`
pointing at numbered entries in `REFERENCES`); `PANEL` in `assets/app.js`
says which of the four diagrams each node belongs to. Add or edit a
reference in `REFERENCES` and point to it by `id` from any node. Never
change a node's `label` or `sub` text without the author team's sign-off —
those fields are the algorithm itself, transcribed verbatim from Figure 1.
